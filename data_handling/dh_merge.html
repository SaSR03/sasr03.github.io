Adding cases and variables

In this chapter, you will learn about how to combine different datasets:

  • Add cases to a dataset (“append files”).

  • Add variables on the same cases from another dataset (“1:1 merge”).

  • Add contextual information to a dataset (“n:1 merge”).

  • *Form all possible combinations of observations in two datasets.

We will elaborate on and illustrate these tasks with simple examples. As a first example, you organize an international data collection, where all countries use the same questionnaire. You obtain datasets from the Netherlands, from the UK, etc. The datasets contain (largely) the same variables. You want to make one dataset of these country datasets, with an additional variable country recording the data source. As a second example, we consider that the two files to be combined contain different variables. We need to distinguish two cases:

  • 1-1 merge: Both datasets contain variables about the same subjects. For example, you have two datasets on countries, one with economic variables, and one with demographic variables. You want to make one dataset in which the observations are countries; the dataset should contain both the economic and the demographic variables.

  • n-1 merge / matched merge / table lookup: The datasets describe different subjects. Example: One dataset describes households, and contains a variable containing the city of residence. The second dataset describes cities, with variables for the number of inhabitants, the political composition of the city council etc. We want to form a dataset on household, in which properties of the city of residence are included. Each household is located in one city, but one city may contain more than one household in the data. This is known as a n-1 link, table lookup or n-1 merge.

A crucial concept in merging is a key. A key comprises one or more variables used to match observations from the two datasets. In the example of 1:1 merging, the key is likely a subject identifier. In the example on n:1 merging, the key is the city identifier. The key variable or variables should occur in both datasets. In R, key variables do not necessarily need to have the same name in both datasets, but using the same name is usually clearer and less error-prone.

PS: The first type of merge is also possible without a key variable or key variables, and strictly on sequential order of the files: the first record of file A with the first record of file B, the second record of file A with the second record of file B, etc. This type of merging is very error prone. We urge you never to merge without keys.

Some notes on combining datasets

  • To append datasets, make sure that corresponding variables in both datasets have the same names, and are coded in the same way. For example, you do not want sex to be coded 0 = male and 1 = female in one dataset, and 0 = female and 1 = male in the other.

  • Issues to consider with key variables for merging:

  • Make sure that the keys are coded identically in both datasets. If you merge on country, the country code should obviously refer to the same country in both datasets.

  • In a 1:1 merge, make sure to always use a key, e.g., the respondent number. Do not rely on the assumption that the first observation in one dataset corresponds with the first observation in the other dataset.

  • R allows composite keys for merging, i.e., the key may consist of multiple variables, e.g., country and year.

  • Do not merge on keys with missing values, unless you really know what you are doing.

  • left_join() keeps all observations from the first dataset and adds matching information from the second dataset. Observations in the first dataset without a match receive NA on the variables from the second dataset.

  • As always: Do not assume that combining files was successful if R does not complain. Check the number of observations. Check the variables. Check values. Check everything.

The trust scales are the real problem. Trust measured on a 5 point scale and trust measured as yes/no are not the same variable, and stacking them into one column would produce a variable whose meaning depends on the year.

# Three defensible options:
#
# 1. Keep them apart. Rename the 2004 items to tcomm_bin, tparl_bin, tcourt_bin
#    so that no column ever mixes the two scales. Honest, but you cannot
#    analyse trust over all three years in one model.
#
# 2. Dichotomise 2000 and 2002 to match 2004. Collapse the 5 point scale into
#    trust yes/no. This throws away detail, but makes all three years
#    comparable on the coarser scale.
#
# 3. Keep both: one column per scale, plus a harmonised binary column that is
#    filled for every year. This is what we do below, because it preserves the
#    original data and still allows a pooled analysis.
#
# What you should NOT do is put 1-5 and 0-1 values in the same column.

# bind_rows() keeps the union of the variables and fills the gaps with NA
# age is missing for every man, educ for every woman
# How does R deal with variables present in only one dataset?
#
# bind_rows() takes the union of the column names and inserts NA where a
# dataset had no such column. It does not warn. The result therefore looks
# perfectly healthy while containing a missing value pattern that is entirely
# an artefact of how the files were combined.
#
# This is why you check the missing values by source after every append. Note
# also that the NAs here are structurally different from real non-response:
# the question was asked, the answer exists, it was simply not in this file.

#   but if you want the common variables only:
