Adding cases and variables

In this chapter, you will learn about how to combine different datasets:

  • Add cases to a dataset (“append cases”).

  • Add variables on the same cases from another dataset (“one-to-one merge”).

  • Add contextual information to a dataset (“many-to-one merge”).

  • Form all possible combinations of observations in two datasets.

We will elaborate on and illustrate these tasks with simple examples. As a first example, you organize an international data collection, where all countries use the same questionnaire. You obtain datasets from the Netherlands, from the UK, etc. The datasets contain (largely) the same variables. You want to make one dataset of these country datasets, with an additional variable country recording the data source.

As a second example, we consider that the two files to be combined contain different variables. We need to distinguish two cases:

  • one-to-one merge: Both datasets contain variables about the same units. For example, you have two datasets on countries, one with economic variables, and one with demographic variables. You want to make one dataset in which the observations are countries; the dataset should contain both the economic and the demographic variables.

  • many-to-one merge / matched merge / table lookup: The datasets describe different units. Example: One dataset describes households, and contains a variable containing the city of residence. The second dataset describes cities, with variables for the number of inhabitants, the political composition of the city council etc. We want to form a dataset on household, in which properties of the city of residence are included. Each household is located in one city, but one city may contain more than one household in the data. This is known as a many-to-one link, table lookup or many-to-one merge.

A crucial concept in merging is a key. A key comprises one or more variables used to match observations from the two datasets. In the example of one-to-one merging, the key is likely a country identifier. In the example on many-to-one merging, the key is the city identifier. The key variable or variables should occur in both datasets. In R, key variables do not necessarily need to have the same name in both datasets, but using the same name is usually clearer and less error-prone.

PS: The first type of merge is also possible without a key variable or key variables, and strictly on sequential order of the files: the first record of file A with the first record of file B, the second record of file A with the second record of file B, etc. This type of merging is very error prone. We urge you never to merge without keys.

We present an R snippet for the four tasks:

Add cases

oecd <- bind_rows(
  world95_oecd_eu,
  world95_oecd_extra
)

one-to-one merge

countries <- left_join(
              world95_3_pop,
              world95_3_rel,
              by = "country" 
            )

Note that in left_join(), the argument by specifies the key variable. If the key variable has the same name in both datasets, you can omit the argument by, but it is good practice to include it for clarity. If the key variable has different names in the two datasets, you can specify them as a named vector, e.g., by = c("country" = "country_name"). If the key is a composite, you can specify multiple variables, e.g., by = c("country", "year").

one-to-many merge

individuals <-  left_join(
                  merge_indiv,
                  world95_3_pop,
                  by = "country"
                )

All combinations of parents and schools

Note that “many-to-many” merges are relatively rare, and creating all combinations of units (which multiplies the number of rows) is very often not what you want. This is why in the code below we have to explicitly tell left_join() that we know what we are doing and really want a many-to-many merge; otherwise it will still produce the combinations but throw a warning.

# Let's specify a fake join key, with the same for all values in both datasets
schools <- schools |>
            mutate(join_key = 1)

parents <- parents |>
            mutate(join_key = 1)

pairs <- left_join(
              parents,
              schools,
              by = "join_key",
              relationship = "many-to-many",
            ) |>
          select(-join_key)


# A more compact way, using tidyr::crossing():
# (will fail if there are variables with the same name in both datasets, line "join_key",
# but can be fixed with the .name_repair argument)
crossing(parents, join_key)

Some notes on combining datasets

  • To append datasets, make sure that corresponding variables in both datasets have the same names, and are coded in the same way. For example, you do not want sex to be coded 0 = male and 1 = female in one dataset, and 0 = female and 1 = male in the other.
  • Issues to consider with key variables for merging:
    • Make sure that the keys are coded identically in both datasets. If you merge on country, a given country code should obviously refer to the same country in both datasets.
    • In a 1:1 merge, make sure to always use a key, e.g., the respondent number. Do not rely on the assumption that the first observation in one dataset corresponds with the first observation in the other dataset.
    • R allows composite keys for merging, i.e., the key may consist of multiple variables, e.g., country and year.
    • Do not merge on keys with missing values, unless you really know what you are doing.
    • left_join() keeps all observations from the first dataset and adds matching information from the second dataset. Observations in the first dataset without a match receive NA on the variables from the second dataset.
    • As always: Do not assume that combining files was successful if R does not complain. Check the number of observations! Check the variables! Check values! Check everything!

1. Synthetic Eurobarometer data

The datasets eurobaro2000_ge, eurobaro2000_nl, and eurobaro2000_uk contain subsets of the Eurobarometer 2000 data, with small selections of respondents from Germany, the Netherlands, and the United Kingdom. These datasets comprise demographic information of respondents, sex and age, and their trust in two institutions of the European Union, the EU commission, tcomm, and the EU parliament, tparl, recorded using 5 point scales. Use bind_rows() to append these three datasets to create one dataset eb2000 for the three countries, adding a string variable country recording the data source. Add a year variable that includes the value 2000.

The datasets eurobaro2002 and eurobaro2004 similarly contain Eurobarometer data for the same three countries for the years 2002 and 2004. We want you to combine these two datasets with eb2000. Make sure that the in the combined dataset there is a variable contaning the year of each survey. However, there are some complications that you have to deal with.

  • the variable Country in 2002: The United Kingdom is not abbreviated to UK as in 2000. (Also note the variable name)
  • the variable country in 2004: It is a labelled numeric variable, not a string variable.
  • the variable sex in 2002 and 2004: The meaning of 1 and 2 are reversed compared to 2000. Use the coding of 2000.
  • in 2002 and 2004, trust was also measured for the European Court of Law.
  • in 2004, trust was measured on a binary scale, 0 = no and 1 = yes, rather than on the 5 point scale used in 2000 and 2002. We do not want to discard information, but also should not bind columns whose values represent different things. Think of a solution and implement it.

We also have two contextual datasets. eudata contains the population size (in September 2012, ignore the mismatch) of these EU countries. The dataset euydata describes the GDP in some EU countries in the years 2000 to 2004, rounded in 1000 EUR units. Make sure you check thge variable names and values before joining. Enrich the individual data with these two contextual datasets using left_join().

3. 1:1 merge: adding variables

In this assignment, we consider how to combine multiple files that comprise different variables for the same subjects. In real life, this may for instance occur in a panel study, in which data from different waves are stored in separate files. We require you create such datasets for training purposes.

  • Use isbs399. This is a variant of sbs399 in which we excluded same-sex households. If you want to, you may consider constructing isbs399 from sbs399 yourself. This dataset comprises couples nested in households and singles. Respondents are identified with hrespnr. Save two subsets of isbs399, one with the variables irespnr, hrespnr, sex, ybirth, and age; the other with irespnr, hrespnr, sex, fage, and fpres.
  • Merge the two files you just created, using irespnr as the key and left_join(). Ascertain that the merged file is correct.
  • Now create the two subsets of isbs399 again, excluding the first observation in the first file, and the second observation in the second file. Merge again on hrespnr using left_join(). Inspect the first two observations. What do you conclude?
    • Extra: experiment with full_join() instead of left_join(). What do you conclude?
  • Merge the two datasets once more, this time matching on hrespnr. Why does it not work? Yes, hrespnr does not uniquely identify observations. The pair hrespnr and sex does uniquely identify subjects, and so they make a valid composite key. Merge on the pair hrespnr and sex, and convince yourself that this leads to the same result as merging on hrespnr.

4. n:1 merge: contextual enrichment

In this assignment we consider how to enrich an individual level dataset with contextual data. The dataset sbs399 contains information on individuals nested in couples or households, identified by the household identifier hrespnr. The dataset hin95_house provides properties of the couple’s house, ownership, number of rooms, etc. Thus, hin95_house also contains the household identifier.

Merge sbs399 and hin95_house on hrespnr using left_join().

The result depends on which dataset you start from. left_join() is not symmetric: rows unmatched on the left (first dataset, in this case part_a2) are kept, rows unmatched on the right (second dataset, part_b2) are silently discarded. So you have to keep in mind that the first dataset is the one you want to keep all rows from, and the second dataset is the one you want to add variables from. full_join() keeps unmatched rows from both sides. This may or may not be what you want.
