Restructuring data

We may present panel data, data on people indicated by id, for different years indicated by year, in long format. To keep things simple, suppose for now that we only measured one time-varying variable, income inc, alongside the time-constant variable male:

id year inc male
1 2000 10 0
1 2001 12 0
1 2002 13 0
2 2000 14 1
2 2001 14 1
2 2002 13 1
3 2000 20 0
3 2002 22 0

or in wide format:

id inc_2000 inc_2001 inc_2002 male
1 10 12 13 0
2 14 14 13 1
3 20 NA 22 0

Be sure that you understand that these two datasets contain the same information, but only represent the information in a different way. One can translate one form into the other form. The variable inc is said to be time-varying, while male is time-constant.

In this part you practice the R functions that restructure data between long format and wide format. You need to learn about this because your data may be in one format, while the data management or statistical method you want to use requires the data to be in the other format.

For instance, multilevel analysis typically requires data to be in long format, e.g., measurements at different time points are stored in different rows, while structural equation modeling often requires wide data, e.g., measurements stored in different variables. In SaSR7 you will learn about these statistical methods. For now, we only introduce how to get the data into the correct format.

R

You should read about the following R functions:

Function Description
pivot_longer() Convert data from wide to long format
pivot_wider() Convert data from long to wide format

Examples:

A single time-varying variable

Restructure long to wide. Every id becomes one row, and the values of year become new column names, prefixed with inc_:

data_wide <- data_long |>
  pivot_wider(
    id_cols = c(id, male),
    names_from = year,
    names_prefix = "inc_",
    values_from = inc
  )

Restructure wide to long. The reverse operation recovers year from the column names, and inc from the values stored in those columns:

data_long <- data_wide |>
  pivot_longer(
    cols = -c(id, male),
    names_prefix = "inc_",
    names_to = "year",
    values_to = "inc"
  )

Several time-varying variables

Things get a little more involved when more than one variable is time-varying, for instance if we also measure a person’s status stat every year:

id year inc stat male
1 2000 10 3 0
1 2001 12 4 0
1 2002 13 5 0
2 2000 14 2 1
2 2001 14 2 1
2 2002 13 2 1
3 2000 20 1 0
3 2002 22 3 0

or in wide format:

id inc_2000 inc_2001 inc_2002 stat_2000 stat_2001 stat_2002 male
1 10 12 13 3 4 5 0
2 14 14 13 2 2 2 1
3 20 NA 22 1 NA 3 0

Now a single column name, e.g. inc_2000, has to be split into two pieces of information: which variable (inc or stat) and which year (2000). pivot_wider() handles this by pivoting on more than one variable at once:

data_wide <- data_long |>
  pivot_wider(
    id_cols = c(id, male),
    names_from = year,
    values_from = c(inc, stat)
  )

Going back to long format, we tell pivot_longer() that one part of the name (.value) becomes the new variable name, inc or stat, and the other part becomes the value of year:

data_long <- data_wide |>
  pivot_longer(
    cols = -c(id, male),
    names_sep = "_",
    names_to = c(".value", "year")
  )

Note that pivot_longer() and pivot_wider() expect that variable names follow a consistent naming convention. In the examples above, the variables are named using a prefix, inc and stat, followed by a year, 2000, 2001, and 2002, corresponding to the level of an index variable, here the year in which income and status were measured, and names_sep = "_" is enough to tell R where the prefix ends and the year begins. If variables are not named consistently, you may need to rename them before restructuring the data.

Sometimes a single separator is not enough, for example when a name mixes a prefix, a single-letter sex code, and a two-digit wave without any separator at all, like inc_m01 or lit_f02. In such cases names_sep cannot locate the boundaries, and pivot_longer()/pivot_wider() instead need a regular expression (via the names_pattern argument) to describe the naming pattern. Regular expressions are a powerful but separate topic that we do not cover in this course; for now, it is enough to know that they exist for naming conventions that names_sep cannot handle.

3. Multilevel data in four formats

The synthetic dataset level4.dta contains multilevel data on three sex-role attitude measurements over time, 2002, 2004, and 2006, for both spouses of heterosexual couples.

  • hhid household id
  • iid individual id
  • urban urbanized
  • male
  • edu highest completed education, 1 to 10
  • year
  • att1 family value: man natural breadwinner
  • att2 family value: women are better with children
  • att3 family value: men and women equal decision makers

We say that the dataset level4 is in long-long-long-wide format for the key variables hhid, iid, year, and (not-existing) item. The first term long refers to households, and reflects that households are stored in different observations identified by hhid. The second term long refers to individuals, and reflects that partners are stored as separate observations identified by iid; the variable hhid allows linking people who form a couple. The third long refers to time: measurements at different time points are stored in different observations, with time indicated by the variable year. The final term wide specifies that the repeated attitude measurements are stored in different variables within an observation, not as different observations.

Make sure that you understand the data well.

  1. Use pivot_longer() to convert the data from long-long-long-wide to long-long-long-long format, i.e., the items are stored in different observations rather than in different variables indexed by a new variable item.
  2. Use pivot_wider() to convert the data from the original long-long-long-wide format to long-long-wide-wide format. Explain what an observation in this dataset represents.
  3. Use pivot_wider() to convert the data from the original long-long-long-wide format to long-wide-wide-wide format, identifying individuals within households by male rather than by iid. What happens if you identify people within households by iid? Is using male as a person-within-household identifier correct if the data include same-sex households?

Which variables are time-constant and which are time-varying? You can answer this by thinking about the meaning of the variables and looking informally at the data.

  • student: a person identifier, so should be time-constant
  • occas: the time index, so it is by definition time-varying
  • sex: time-constant
  • gpa: time-varying, can change each semester
  • job: time-varying: working hours change between semesters
  • highgpa: time-constant, as it’s the final high school GPA
  • admitted: time-constant, there is a single admission decision per student

But to be sure we can check the number of distinct values of each variable within each student. If a variable has more than one distinct value for a student, it is time-varying; if it has only one distinct value, it is time-constant.

gpa2long_again <- gpa2wide |>

    cols = -c(student, sex, highgpa, admitted),

What would happen if we used iid instead of male? iid is unique across the whole dataset, not just within a household. Using it as the person-within-household index would create one pair of columns for every individual in the data, so the result would have as many column groups as there are people, almost all of them missing for any given household. The dataset would be enormous and unusable.

Is male a correct person-within-household identifier? Only for heterosexual couples, which is what this synthetic dataset contains. In a same-sex household both partners share the same value of male, so the pair no longer identifies them uniquely. pivot_wider() wouldfind two values for one cell and return a list column with a warning about duplicate identifiers, rather than the intend two sets of columns.

One solution would be creating a gender-neutral unique identifier within each houseold (partner 1, partner 2), and use that instead:

level4 |>
  mutate(
    partner = dense_rank(iid),
    .by = hhid
  ) |> 
  pivot_wider(
    id_cols = c(hhid, urban),
    names_from = c(partner, year),
    values_from = c(att1, att2, att3, edu),
  )
