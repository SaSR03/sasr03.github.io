Restructuring data

We may present panel data, data on people indicated by id, for different years indicated by year, in long format:

id year inc stat male
1 2000 10 3 0
1 2001 12 4 0
1 2002 13 5 0
2 2000 14 2 1
2 2001 14 2 1
2 2002 13 2 1
3 2000 20 1 0
3 2002 22 3 0

or in wide format:

id inc2000 inc2001 inc2002 stat2000 stat2001 stat2002 male
1 10 12 13 3 4 5 0
2 14 14 13 2 2 2 1
3 20 NA 22 1 NA 3 0

Be sure that you understand that these two datasets contain the same information, but only represent the information in a different way. One can translate one form into the other form. The variables inc and stat are said to be time-varying, while male is time-constant.

In this part you practice the R functions that automatically restructure data between long format and wide format. You need to learn about this because your data may be in one format, while the data management or statistical method you want to use requires the data to be in the other format.

For instance, multilevel analysis typically requires data to be in long format, e.g., measurements at different time points are stored in different rows, while structural equation modeling often requires wide data, e.g., measurements stored in different variables. In SaSR7 you will learn about these statistical methods. For now, we only introduce how to get the data into the correct format.

R

You should read about the following R functions:

Function Description
pivot_longer() Convert data from wide to long format
pivot_wider() Convert data from long to wide format

Examples:

Restructure long to wide:

data_wide <- data_long |>
  pivot_wider(
    id_cols = c(id, male),
    names_from = year,
    values_from = c(inc, stat)
  )

Restructure wide to long:

data_long <- data_wide |>
  pivot_longer(
    cols = -c(id, male),
    names_to = c(".value", "year"),
    names_pattern = "(.*)(\\d{4})"
  )

Note that pivot_longer() and pivot_wider() expect that variable names follow a consistent naming convention. In the example above, the variables are named using a prefix, inc and stat, followed by a year, 2000, 2001, and 2002, corresponding to the level of an index variable, here the year in which income and status were measured. If variables are not named consistently, you may need to rename them before restructuring the data.

2. Sex-specific country indicators

In this assignment, we use the World95 dataset. This dataset contains information for 109 countries. One observation corresponds to one country.

Some variables are sex-specific, e.g., the life expectancy for men and women (lifeexpm and lifeexpf respectively) and the literacy rates of men and women (lit_male and lit_female respectively). Other variables, e.g., populatn and density, are not sex-specific.

We want to create a dataset in which each country is represented by two observations, one describing the men and one describing the women of that country.

A new dummy variable female should describe whether a record pertains to women or men.

3. Multilevel data in four formats

The synthetic dataset level4.dta contains multilevel data on three sex-role attitude measurements over time, 2002, 2004, and 2006, for both spouses of heterosexual couples.

hhid household id

iid individual id

urban urbanized

male

edu highest completed education, 1 to 10

year

att1 family value: man natural breadwinner

att2 family value: women are better with children

att3 family value: men and women equal decision makers

We say that the dataset level4 is in long-long-long-wide format for the key variables hhid, iid, year, and the not-yet-existing variable item.

The first term long refers to households, and reflects that households are stored in different observations identified by hhid.

The second term long refers to individuals, and reflects that partners are stored as separate observations identified by iid; the variable hhid allows linking people who form a couple.

The third long refers to time: measurements at different time points are stored in different observations, with time indicated by the variable year.

The final term wide specifies that the repeated attitude measurements are stored in different variables within an observation, not as different observations.

Make sure that you understand the data well.

  1. Use pivot_longer() to convert the data from long-long-long-wide to long-long-long-long format, i.e., the items are stored in different observations rather than in different variables indexed by a new variable item.

  2. Use pivot_wider() to convert the data from the original long-long-long-wide format to long-long-wide-wide format. Explain what an observation in this dataset represents.

  3. Use pivot_wider() to convert the data from the original long-long-long-wide format to long-wide-wide-wide format, identifying individuals within households by male rather than by iid.

  • What happens, or would happen, if you identify people within households by iid?
  • Is using male as a person-within-household identifier correct if the data include same-sex households?

# What would happen if we used iid instead of male?
#
# iid is unique across the whole dataset, not just within a household. Using
# it as the person-within-household index would create one pair of columns
# for every individual in the data, so the result would have as many column
# groups as there are people, almost all of them missing for any given
# household. The dataset would be enormous and unusable.
#
# A within-household sequence number would work: number the partners 1 and 2
# within each household, and pivot on that.
level4 |>
  mutate(
    partner = dense_rank(iid),
    .by = hhid
  ) |>
  pivot_wider(
    id_cols = c(hhid, urban),
    names_from = c(partner, year),
    values_from = c(att1, att2, att3, edu),
    names_prefix = "p"
  ) |>
  nrow()

# the same number of households, using a within-household index
# Is male a correct person-within-household identifier?
#
# Only for heterosexual couples, which is what this synthetic dataset
# contains. In a same-sex household both partners share the same value of
# male, so the pair no longer identifies them uniquely. pivot_wider() would
# find two values for one cell and return a list column with a warning about
# duplicate identifiers, rather than the intended two sets of columns.
#
# The within-household sequence number above does not have this problem. It
# does, however, lose the substantive meaning that "partner 1 is the man",
# so any analysis comparing partners has to carry male along as a separate
# variable.
level4 |>
  summarise(n_male = n_distinct(male), .by = hhid) |>
  count(n_male)
